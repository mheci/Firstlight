# AGENTS.md — Firstlight

Working instructions for AI agents and contributors on this repository. This is a **BlueBuild** repository that produces a Fedora 44 Atomic (bootc) container image, published to GHCR as `ghcr.io/mheci/firstlight`.

## What this image is

A personal, gaming/creative/AI-focused **Fedora 44 Kinoite** atomic desktop (KDE Plasma 6):

- **Base**: `ghcr.io/blue-build/base-images/fedora-kinoite`, `image-version: "44"`. **Plasma 6.6.x** on Wayland; login via **SDDM** (Plasma's display manager).
- **NVIDIA open drivers (DKMS) + CUDA toolkit** from the NVIDIA fedora44 repo; **Terra mesa** (preferred over Fedora's, epoch-0 vs epoch-1).
- **Kernel**: CachyOS kernel (COPR `bieszczaders/kernel-cachyos`); Secure Boot is **machine-local** — a key generated on each machine in `/var/lib/firstlight-mok` signs the CachyOS kernels/modules (boot service + `just sb-setup`), never baked into the image; stock Fedora kernel kept as signed fallback.
- **Terra (repos.fyralabs.com) is the PRIMARY package source**; Fedora base and RPM Fusion (repos only) are fallbacks.
- **Plasma theming (all prebuilt RPMs)**: Klassy (decorations), Darkly (widget style), Bibata cursors, Breeze-Plus icons, Fluent look-and-feel (from Terra); **Vapor** (Steam Deck look) from COPR `ublue-os/bazzite` (`steamdeck-kde-presets-desktop`). Defaults applied image-wide to `/etc/xdg/*` via `kwriteconfig6` AFTER the Vapor install (Vapor ships its own `/etc/xdg` drop-ins — merging, never overwriting). Kinoite is shipped **stock** (no bloat removal — PIM daemons, RDP/VNC servers, first-run wizards and the CJK `fcitx5` stack remain from the base image).
- **KWin scripts** (vendored into the repo under `files/system/usr/share/kwin/scripts/`, enabled system-wide via `/etc/xdg/kwinrc` `[Plugins]` keys): **Krohnkite** (dynamic tiling, declarativescript) + **Alt-F4 Desktop** (Alt+F4 on the desktop shows the logout prompt).
- **Gaming**: Steam, Proton-CachyOS, umu, faugus-launcher, ScopeBuddy, stable scx schedulers + scx-manager, terra-gamescope, ananicy-cpp, NTSync, falcond.
- Reliability: greenboot (greenboot-rs) health checks + auto-rollback after 3 failed boots. **Coredumps fully disabled** (`/etc/systemd/coredump.conf.d/00-disable.conf`).
- AI: CUDA llama.cpp (conda-forge), whisper.cpp (official prebuilt binaries, CPU build), Open WebUI (quadlet container), Hermes, Unsloth, glance.
- **No-source-build policy**: NOTHING is compiled in the image. whisper.cpp uses the official `whisper-bin-ubuntu-x64.tar.gz` release asset; wl-clip-persist comes from the `leloubil` COPR RPM; llama.cpp from conda-forge; handlr-regex from its release binary; bun/pi via official release assets. This is a hard user decision.

## Hard constraints (do not violate)

1. **Never delete or recreate this repository.** Only commit/push changes to it.
2. **Never run local builds/downloads of the image** in this session. Lightweight verification via `gh api`/`gh run`/`gh workflow run`, webfetch, or subagent research is allowed.
3. **Never guess — verify.** Before assuming any package/version/behavior, confirm against official docs, package repos (packages.fedoraproject.org, terrapkg github, COPR API), or a research subagent. Cite sources.
4. **Poll CI at intervals ≤ 2 minutes.** Never longer.
5. **No secrets.** `SIGNING_SECRET` lives in GitHub secrets; the MOK private key is **generated per machine at runtime** (no key material in the repo, image, or CI — the old `FIRSTLIGHT_MOK_KEY` secret + build-time signing were removed 2026-08-20); never print or commit secrets. Remind the user to revoke any exposed PAT when wrapping up.
6. **Never add comments to code unless they add real context** (this repo's scripts use concise purpose comments — match that style).
7. **Never remove the `example.sh` template** and preserve exec bits on all scripts.

## Engineering values & priorities

1. **Native-first packaging.** Prefer, in order: official maintainer/dev repo → Terra → RPM Fusion → Fedora base → official release tarball/prebuilt binary → third-party COPR. Only use Flatpak if no reliable native path exists. **Never build from source** (user decision 2026-08-20).
2. **Stable-over-nightly (per user decision).** All Terra/Fedora nightlies were replaced with stable packages: yt-dlp + mpv from Fedora, scx-scheds/scx-tools stable from Terra, scx-manager from the CachyOS addons COPR; bpftune-nightly was **dropped** (no stable bpftune exists in Fedora or Terra). bun pinned to a release binary (v1.3.14, official GitHub asset — scorecard Pinned-Dependencies); bun-installed pi stays latest. Direct download URLs are pinned to release tags (glance, handlr v0.13.0, betterbird + sha256, whisper v1.9.2) — `releases/latest` drifts silently on rebuilds. Pin only when upstream has no stable channel.
3. **bootc/atomic correctness.** The image is built inside a container **with no running systemd**:
   - `systemctl daemon-reload`, `systemctl start`, and quadlet enables will FAIL at build time.
   - `systemctl enable <regular-unit>` works offline (symlink ops). For quadlet units, create the enable symlink manually (`ln -sf <name>.container → /etc/systemd/system/multi-user.target.wants/<name>.service`).
   - `/var` is a bootc VOLUME: `setsebool -P` at build does NOT persist → ship a boot-time oneshot unit instead (see `selinux-gaming.sh`).
   - `/usr` is read-only at runtime; per-user state belongs in `/etc/skel` or first-boot services.
   - `/etc` is mutable + persistent on ostree: files shipped under `files/system/etc/*` (sysctls, environment, coredump.conf.d, kwinrc/xdg config) survive reboots/upgrades.
4. **Package conflicts are resolved deliberately**: use `--allowerasing` only to erase an explicitly-unwanted conflicting package (e.g. `libfdk-aac`, `zram-generator-defaults`, `gamemode` via falcond, Fedora's `gamescope` via terra-gamescope); never to silently drop wanted packages. If a Terra package is broken (e.g. `pi`'s bogus riscv64 Requires), fall back to bun/github and comment why.
5. **No VLC, ever. mpv is the media player.** No Flatpak. No `80-gamecompatibility.conf` naming — the gaming sysctl file is `/etc/sysctl.d/99-gamecompatibility.conf`.
6. **Plasma defaults are written with `kwriteconfig6 --file /etc/xdg/<file>`** (merges into the file, preserving keys) — never `cat >` over `/etc/xdg/*` files that Vapor or other packages own. KWin scripts are enabled via `kwinrc` `[Plugins]` keys `<Id>Enabled=true`; script packages live in `/usr/share/kwin/scripts/<Id>/` (metadata.json at package root + `contents/code/main.js` or `contents/ui/main.qml`). Plasma 6 uses metadata.json only (metadata.desktop is deprecated).
7. **GitHub-API-free downloads in build scripts** where possible (use `/releases/<tag>/download/` or `/releases/latest/download/` redirects or master tarballs) — the API rate-limits (403) and broke builds before.
8. **Rust-first CLIs.** Prefer Rust utilities over C/unsafe equivalents (ripgrep, fd, bat, eza, zoxide, du-dust, procs, starship, bottom are all installed).

## Build & verification workflow

1. Make changes; ensure new scripts are listed in `recipes/recipe.yml` and have the exec bit.
2. `git add -A && git commit -m "<summary>" && git push`.
3. Trigger a build: `gh workflow run build.yml --repo mheci/Firstlight` (the push may already auto-build).
4. Poll: `gh run view <id> --repo mheci/Firstlight --json status,conclusion` — **at most every 2 minutes**; wait for `completed success`.
5. On failure: `gh run view <id> --repo mheci/Firstlight --log-failed` and fix the root cause.
6. (ISO builds were removed; the forked `mheci/build-container-installer` repo and its image were deleted.)

## Key technical facts (verified; avoid re-researching)

- Terra bootstrap: `dnf install -y --nogpgcheck --repofrompath 'terra,https://repos.fyralabs.com/terra$releasever' terra-release terra-gpg-keys`, then priority via `sed -i 's/^\[terra\(.*\)\]/[terra\1]\npriority=1/' /etc/yum.repos.d/terra.repo /etc/yum.repos.d/terra-mesa.repo`. **`$releasever` resolves to `44` on the bootc image** (derived from the RPMDB's `fedora-release`), so Terra's `terra$releasever` URL → `terra44`, and COPR `fedora-$releasever` URLs → `fedora-44` — all verified against live repo listings.
- Mesa: `dnf downgrade -y --disablerepo=fedora --disablerepo=updates mesa-dri-drivers mesa-vulkan-drivers mesa-libGL mesa-libEGL mesa-libgbm` (Terra epoch 0 vs Fedora epoch 1).
- fdk-aac: `dnf install -y --allowerasing fdk-aac fdk-aac.i686` (Fedora `libfdk-aac` Obsoletes conflict).
- RPM Fusion: repos only (`enable-rpmfusion.sh`); `gstreamer1-plugins-bad-freeworld/ugly` deliberately excluded (x265-libs 4.1 vs Terra 4.2).
- **Plasma theme packages (Terra, fc44, all prebuilt — verified 2026-08-20 against terra44 repodata)**: `klassy` 6.7.1 (window decorations + Plasma style), `darkly` 0.5.38 (Lightly-fork Qt widget style), `bibata-cursor-theme` 2.0.7 (Modern/Oil/Classic cursors), `breeze-plus-icon-theme` 6.28.0, `fluent-kde-theme` (+ `fluent-kde-theme-sddm` subpackage). **Vapor**: `steamdeck-kde-presets-desktop` from COPR `ublue-os/bazzite` (fc44 chroot, noarch; provides Vapor + VGUI look-and-feels, wallpapers, `/etc/xdg` drop-ins for kdeglobals/kwinrc/etc; no package conflicts on stock Kinoite; ships NO SDDM theme). `install-kde-plasma.sh` merges our defaults AFTER the Vapor install because Vapor overwrites `/etc/xdg/kwinrc`.
- **KWin scripts**: system-wide install dir is `/usr/share/kwin/scripts/<Id>/` (metadata.json at root, `contents/code/main.js` for javascript API, `contents/ui/main.qml` for declarativescript; `KPackageStructure: "KWin/Script"`). Enable: `kwriteconfig6 --file /etc/xdg/kwinrc --group Plugins --key <Id>Enabled true`. Krohnkite fork `anametologin` (min API 6.0) + Alt-F4 Desktop `micha4w` (min API 6.1) are vendored in this repo. Plasma 6 accepts metadata.json only.
- NVIDIA env (2026-08, driver 595 + Plasma 6.6, Wayland): **no `GBM_BACKEND` needed** (KWin GBM works since 495; 560+ has DRM default on); `__GLX_VENDOR_LIBRARY_NAME=nvidia` forces GLVND NVIDIA GLX (only needed for PRIME/hybrid, harmless single-GPU); `LIBVA_DRIVER_NAME=nvidia` only if `nvidia-vaapi-driver` is installed (it isn't). `ELECTRON_OZONE_PLATFORM_HINT` is **obsolete** (removed in Electron 38 — `--ozone-platform=auto` is default). NVIDIA shader cache is on by default; `/etc/environment` sizes it (10 GiB) + `SKIP_CLEANUP`. Qt 6 shader disk cache is on by default (`QSG_RHI_PIPELINE_CACHE_SAVE`) — nothing to enable.
- **whisper.cpp v1.9.2** (install-whisper-cpp.sh): official PREBUILT Linux asset `whisper-bin-ubuntu-x64.tar.gz` (ubuntu-22.04/glibc 2.35 → runs on F44's glibc 2.42), containing whisper-cli/server/quantize/bench + libwhisper/libparakeet/libggml* (CPU variants auto-selected). The CUDA release assets (`whisper-cublas-*.zip`) are **Windows-only** (verified); the only Linux CUDA route is the ggml-org container (needs nvidia-container-toolkit, unavailable) — so the CPU prebuilt is the no-source-build choice. **Installs to `/usr/bin` + `/usr/lib`, NOT `/usr/local/*`** — the base image's `/usr/local` is a symlink that doesn't resolve in the build container (whisper's `/usr/local/lib/` `install -D` failed with "target ... No such file or directory"; `/usr/local/bin` happens to exist so `install -D` works there, but `/usr/local/lib` does not — avoid `/usr/local/*` entirely, same pitfall as the SB signer).
- **wl-clip-persist**: no Fedora/Terra/RPM-Fusion package, GitHub releases are source-only (verified) → prebuilt RPM `wl-clip-persist-0.4.1` from COPR `leloubil/wl-clip-persist` (fedora-44 chroot) via `--repofrompath`. Autostart has `OnlyShowIn=KDE`.
- **kernel-cachyos + Secure Boot (machine-local since 2026-08-20)**: kernel + devel install in `install-kernel-cachyos.sh` (NOT the dnf module) with `--setopt=tsflags=noscripts`: the cachyos kernel-core %posttrans runs `kernel-install`/dracut before its own kernel-modules %posttrans depmod, so the dracut step dies on a missing modules.dep in container builds (`/run/ostree-booted` guard doesn't exist there). Scriptlets are safe to skip — bootc generates initramfs + BLS entries on the machine at deploy. The script then runs `depmod` **per installed kernel version** (plain `depmod -a` resolves `uname -r`, which inside the build container is the host runner kernel, e.g. `6.17.0-1022-azure`, that has no /lib/modules dir — it must never be used), installs `kmod-nvidia-open-dkms` + `nvidia-driver` (dkms %post builds for both stock and cachyos kernels; `nvidia-open` is precompiled for the stock kernel only and must NOT be used), and enables nvidia-persistenced. **Signing is a runtime concern**: `install-secureboot.sh` ships `usr/bin/firstlight-sb-sign` + `firstlight-sb-sign.service` (enabled) + `just sb-setup/sb-enroll/sb-status`. The signer runs on every boot on UEFI+Secure-Boot machines, generates a per-machine RSA-4096 keypair once in `/var/lib/firstlight-mok/` (persists across bootc deployments), signs the **CachyOS-only** kernels/modules of EVERY deployment via its writable on-disk path `/ostree/deploy/*/deploy/*/usr/lib/modules/` (never the read-only live `/usr` mount; the stock Fedora kernel keeps its Fedora signature as the pre-enrollment fallback), decompresses `.ko.xz/.ko.zst` → signs the ELF with `/usr/src/kernels/*/scripts/sign-file` → recompresses to `.ko.xz`, and queues the one-time MOK enrollment with a random password (written to `/etc/motd.d/99-firstlight-sb.conf` + `/var/lib/firstlight-mok/enroll-password`); completion = reboot → MOK Manager → Enroll MOK → password. Enrollment is detected via `mokutil --test-key`; `mokutil --sb-state` gates non-SB machines. **Rationale**: the old design baked the MOK private key into the public image and signed at build time (FIRSTLIGHT_MOK_KEY secret, cert.pem/db.der in `files/system/etc/pki/firstlight-mok/` — all removed); a leaked key would let anyone sign arbitrary modules trusted by enrolled machines. Per-machine keys keep every machine's trust anchor local and make onboarding self-service: boot → one reboot to enroll → automatic forever.
- **greenboot**: packages `greenboot` + `greenboot-default-health-checks` (the Rust rewrite, v0.16.x, present in Fedora 44 release/updates repos — verify with the mirror listing, NOT packages.fedoraproject.org which is stale for this package). `install-greenboot.sh` enables `greenboot-healthcheck.service`; the default-health-checks subpackage ships the network-online drop-in. Shipped `greenboot.conf`: `GREENBOOT_MAX_BOOT_ATTEMPTS=3`, `DISABLED_HEALTHCHECKS` (01_repository_dns_check.sh, 01_update_platforms_check.sh), `GREENBOOT_WATCHDOG_GRACE_PERIOD=1`, `GREENBOOT_WATCHDOG_CHECK_ENABLED=true` (keys read by required.d/02_watchdog.sh).
